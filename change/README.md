# Change Workflow

This directory stores the current change intake and its event history.

## Files

- `current.json` stores the active change intake.
- `history.jsonl` stores append-only change events.
- `intake.md` is generated by `change scaffold` as the human-readable intake scaffold.
- `scout` can infer a change from git status when the repo already has modified files.

## Commands

- `change scout` inspects the repository and prints a task lock without writing.
- `change auto-scaffold` infers the change and writes the current intake plus scaffold.
- `change analyze` captures the current task lock.
- `change scaffold` writes the intake markdown scaffold.
- `change preview` shows the intake plus gate status without writing.
- `change apply` writes the intake and scaffold files in one step.
- `change diff` compares the current intake against the last gate.
- `change rollback` restores the last committed change intake snapshot.
- `change gate` checks whether the change is ready to ship.
- `change gate` also captures a note into `memory/change/<profile>.md`.
- A successful `change gate` also runs `memory learn` so repeated lessons can move into profile memory automatically.
- `change memory-suggest` proposes durable lessons to promote from change memory.

## Expected flow

1. Analyze the change intent.
2. Scaffold the intake and required files.
3. Run the gate before delivery.
